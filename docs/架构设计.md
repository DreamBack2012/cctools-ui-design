# CCTools 新版架构设计

## 目标与范围

新版围绕设备工作流组织界面：统一发现和选择设备，在原地发起单台或批量操作，集中跟踪进度与逐台结果。

本工程是浏览器交互原型，供本地讨论和团队评审使用，不连接控制器、不执行真实烧录、不使用真实账号。
参考站点为 <https://fangye945a.github.io/ct16_test/>，借鉴其统一导航和工作区组织方式；
参考站点面向单台 CT16 的 Web 管理，CCTools 面向多台设备、多个型号与本地烧录，业务边界不同。
页面、图标和样式在本工程重新实现，没有复制站点程序或遥测脚本。Excel 交互使用本地随附的 SheetJS，仅用于浏览器评审。

业务字段、型号映射和版本限制以[现有功能对应表](现有功能对应表.md)为准；该表同时列出尚未展开的既有功能。

正式工具继续采用 Qt Widgets；网页原型不意味着将桌面程序改为 Web 应用。
本轮不修改现有 CCTools，不发布 GitHub，不替换现有协议、密码算法或烧录工具。

## 信息架构

| 工作区 | 主要职责 | 设备选择方式 |
| --- | --- | --- |
| 设备工作台 | 搜索、连接、筛选、单台管理，发起批量操作 | 全局设备列表 |
| 任务中心 | 所有长任务的整体进度、逐台结果、错误、日志和失败重试 | 任务创建时的目标快照 |
| 右侧设备管理页签 | 单台概览、参数管理、日志终端、文件管理 | 点击设备名称确定当前设备，与批量勾选分别标明 |
| 底部结果区 | 当前任务逐台结果、日志、LED 确认、失败重试 | 任务目标快照，可切换查看其他任务 |
| 固件烧录 | 主控、子板、蓝牙/星闪、WiFi 烧录 | 独立的 USB / 串口 / J-Link 目标 |
| 生产测试 | PCBA、整机、老化，测试项方案、SN 烧录和结果导出 | 工位目标，沿用共享设备身份 |
| 设备模型（后续独立设计） | 保留现有配置、状态、控制编辑能力，本轮不以简化草稿代替完整编辑器 | 无需设备选择 |
| 设置 | 连接、全局偏好、账号与工具信息 | 全局设置；操作文件不放在此处 |

正式软件仍通过现有构建宏决定内测、发行与工厂版本，没有运行时版本切换功能。
窗口外“原型预览”工具条切换 URL，独立于正式产品窗口；也可直接使用以下参数预览版本入口：`?edition=release` 和 `?edition=factory`。
生产测试仅在工厂版显示，工厂版默认进入生产测试；远程调试仅内测版开放，会话密钥配置仅发行版显示。
工厂版不开放文件管理、配置备份及配置文件导入。内测版设备模型编辑器后续单独设计。

设备工作台仍对工厂版开放统一目标选择，避免再次建立一套重复设备列表。
工厂操作员的默认首页保留生产测试，减少日常操作路径。

## Qt Widgets 实现约束

本设计面向现有 Qt 5.14.2、MinGW、Qt Widgets 工程。网页仅用于预览，不作为正式软件的服务端或运行容器，
不要求增加 Web 服务、Electron、QWebEngine 或 QML。

| 原型界面 | Qt 实现方式 | 对现有工程的影响 |
| --- | --- | --- |
| 主窗口、左侧导航、状态栏 | 保留现有 QUIWidget 窗口框架，使用 QHBoxLayout / QVBoxLayout、QListWidget、QStackedWidget、QStatusBar | 调整主窗口布局与页面组织，不重写窗口基础库 |
| 设备列表与筛选 | QTableView + QAbstractTableModel + QSortFilterProxyModel；复选列与操作委托 | 在 DeviceManager 之上共享设备模型，避免每页复制列表 |
| 主窗口操作页签 | QSplitter + QTabWidget + QWidget；文件、目标、差异预览和执行按钮在同一面板 | 不以模态向导承载日常业务；切换页签保留表单草稿 |
| 文件选择、保存与文件分配 | QFileDialog、QLineEdit、QComboBox / 表格委托，QXlsx、QFile / QSaveFile | 复用现有 Excel 读写和文件操作，不增加上传服务器步骤 |
| 参数差异预览 | QComboBox 选择设备，QTableView 展示参数、当前值和目标值 | 逐台读取真实参数并展示差异，不用固定示例值替代查询结果 |
| 设备管理页签 | 右侧 QWidget + QTabWidget；概览、参数、日志、文件各自封装 | 与左侧列表同时可见，复用既有终端、文件与参数控件 |
| 底部结果与任务列表 | QDockWidget 或纵向 QSplitter；QTableView / QTreeView + QPlainTextEdit；任务选择框、逐台结果和日志 | 执行后更新底部区域，不弹任务窗口；数据由 TaskService 持有 |
| 日志、错误与人工确认 | 底部 QPlainTextEdit、行内错误和 LED 确认按钮；必要危险操作用 QMessageBox | LED 等待在结果区处理，不阻塞操作工作区或工作线程 |
| 烧录接口和外部进程 | QSerialPortInfo、现有 Windows USB 检测、QProcess 异步信号 | 沿用现有驱动检测和烧录后端，不要求 HTTP API |
| 全局偏好和任务记录 | 现有 QtSettings / QSettings 与 SQLite 管理器 | 密钥沿用当前安全机制，不写入普通任务日志 |

窗口以桌面尺寸设计，最小工作宽度暂按 1100 像素评审。正式实现通过 Layout、sizeHint、
minimumSize 与 Windows 高 DPI 缩放适配，不照搬浏览器像素坐标，也不设计手机端布局。

界面只展示待实现的功能、参数、状态和必要操作提示。宣传标语、架构说明、演示按钮、
故障注入、版本视角切换以及未经完整设计的模型草稿页均不放入产品页面。
样例数据、原型编解码限制、测试入口和实现说明统一放在本文与 README。

任务与桌面进程同生命周期，切换页面可以继续执行，关闭程序不等同于切换页面。
有固件写入等关键任务时，主窗口在 closeEvent 中阻止直接退出，并提示返回任务；
不能声称关闭工具后仍由后台服务器继续烧录。异常退出后仅恢复记录并标记中断，不自动重发写操作。

以上控件均可由现有 Qt Widgets 技术栈实现；本轮未编写或编译 Qt 界面实现，
不把浏览器验证作为 Qt 构建、设备协议或真实烧录验证。

工作台以 QTabBar、紧凑工具栏、QTableView 与底部状态栏为核心；不使用仪表盘式统计卡片。发现、连接和选择数量在状态栏呈现，任务数量在导航与状态栏呈现。

## 核心操作流程

### 发现、连接与批量操作

1. 在设备工作台设置完整起止 IPv4 地址（第三、第四段均独立可编辑），再搜索设备；按编号、SN、型号、地址或状态筛选。
2. 勾选设备，点击连接；明确区分发现、已连接和离线。
3. 在当前页面发起配置、OTA、导出或重启，操作面板直接带入目标。
4. 准备文件与参数，查看逐台能力检查和参数预览。
5. 核对当前面板列出的目标，点击明确命名的执行按钮。
6. 在主窗口底部查看逐台结果、展开日志或重试失败设备；任务中心用于集中查询，不是必经入口。

筛选和切换局域网 / 云端时保留已选设备，计数显示完整选择；执行面板必须列出全部目标，
不能只展示当前可见的列表。任务创建后不再引用界面勾选集合。

### 配置导入与批量参数修改

- 统一配置：从 Excel 明确选择一个来源 SN 行，将可用参数应用到多台设备。
- 逐台分配：选择 Excel 文件，按目标 SN 对应行分配；不按文件顺序隐式对应。
- 文件选择、校验、预览、执行在同一个操作面板中完成，不依赖设置中的全局文件路径。
- 没有配置文件时可以从工作台发起导出。备份是配置来源和可选保护措施，不是每次导入的必经步骤。
- 最终按钮明确写“执行导入配置”“执行批量配置”等，并显示可执行设备数量；执行后在底部显示结果，不切走输入页。单台编辑保留既有保存操作。
- 正式版检查 Excel 工作表、参数键、值类型、范围、只读项与型号能力。原型读取现有工作表结构的 Excel 普通值单元格，不定义新的产品配置格式。
- 正式版差异预览必须逐台展示真实当前值；原型使用标明的示例当前值，逐台分配列出文件关系。
- 可选执行前备份；原型保留模拟参数快照并可在任务详情保存到本机，正式版备份文件需有可查找的保存位置。
- 不承诺跨设备原子事务。部分成功时保留每台设备结果，已成功项不随其他设备失败而回滚。

### OTA

目标来自设备工作台，不再重复建立升级设备列表。沿用现有的逐台固件检查，不在界面层一律禁止混合型号；
是否适配由固件头的芯片、产品字段及签名决定。不增加人工指定固件型号的控件。

正式升级细分为传输、校验、写入、重启和重连验证，不能用传输 100% 代替升级成功。
原型只演示进度和错误，不实现真实固件解析或这些硬件阶段。

### 任务与恢复

每个任务包括操作类型、不可变目标快照、操作参数、创建时间、逐台状态与日志。

逐台状态：排队、执行中、等待人工确认、成功、失败、取消。
任务有部分失败时保留所有结果；“仅重试失败设备”创建带来源 ID 的新任务，不重跑成功设备。

同一设备有活跃任务时禁止重复发起冲突操作。正式版按资源类型细分：
设备会话、文件传输通道、串口、USB 目标和下载器；不同设备是否允许并发由执行器能力决定。
原型采用每任务最多两台并发和同设备互斥，尚未实现跨任务的全局并发配额。

只允许取消排队设备。正在写固件等不可安全终止的任务不提供强制取消。
切换页签和页面都不取消任务，也不清空操作草稿；任务刷新仅更新结果区，避免打断输入。

原型的任务仅保存在内存，刷新即清空。正式版采用 SQLite 保存任务与结果；
应用重启后将未完成任务标为中断，重新检查设备状态，由用户确认后重试，不盲目自动续写。

### 工厂与烧录

PCBA / 整机 LED 测试等待人工确认，不超时自动通过；老化不弹人工确认。
原型提供 23 项选择、阶段参数与 LED 确认；老化连续循环，轮间等待 5 秒，停止后结束。完整测试历史统计沿用后续正式迁移计划。

网络设备身份和烧录接口身份分别建模，不要求先网络连接才能烧录。
烧录目标按当前 USB 设备、串口或下载器身份加锁，不能因为切换产品或部件就绕过同接口互斥。
后端继续按 Rockchip、J-Link、ESP、FnLink / BurnTool 等方案组织，产品通过 Profile 配置映射。

## 正式 Qt 分层建议

```text
AppShell / 版本与功能入口
    ├─ DeviceWorkspace / DeviceDetails
    ├─ OperationPanel / 参数与目标预览
    ├─ TaskCenter / TaskDetails
    ├─ FlashWorkspace / ProductionWorkspace
    └─ DeveloperTools / Settings
                │
OperationRegistry / OperationDefinition
    校验输入、计算能力、生成目标与参数快照
                │
TaskService / TaskRepository
    调度、互斥、取消边界、逐台状态、重试、结果持久化
                │
OperationExecutor
    参数 / 配置 / 文件 / OTA / 激活 / 工厂测试 / 烧录执行器
                │
现有设备管理、协议、文件传输与烧录后端
```

| 部件 | 职责与边界 |
| --- | --- |
| DeviceRepository | 包装现有 DeviceManager，维护唯一设备身份、发现地址、连接状态与能力；页面使用共享模型或代理模型 |
| SelectionContext | 保存全局目标选择；任务提交时转成快照；不由业务页面各自存另一份设备表 |
| CapabilityService | 产品基线 + 固件实际能力 + 连接状态 + 操作依赖；未知能力不猜测为支持 |
| OperationDefinition | 操作标识、输入模型、校验、预览、取消边界和执行器创建；不直接操纵 QWidget |
| TaskService | 持有任务生命周期，提供进度信号；不依赖某个页面存活 |
| ResourceCoordinator | 管理会话、串口、USB、下载器等资源，统一排队与互斥 |
| TaskRepository | SQLite 中保存任务参数摘要、目标、逐台结果与日志索引，不记录明文密钥 |
| OperationExecutor | 适配既有业务控制器 / 协议与文件传输；异步返回阶段、进度与错误 |
| Views / ViewModels | 表单、列表、预览和交互；不发送协议，不自建线程调度器 |
| EditionPolicy | 保留内测、发行、工厂版本的功能入口与权限，不能只通过隐藏按钮实现授权 |

跨线程数据通过 Qt 信号传递；QObject 的线程归属和数据库连接归属必须明确。
网络操作、文件传输与外部烧录进程不在 GUI 线程同步等待。

操作失败应区分连接、输入校验、传输、设备拒绝、设备超时和后端错误，保存英文开发日志，
给用户提供中文原因、目标和建议动作。任务进度需要业务阶段，不只显示百分比。

## 产品能力约束

根据当前 CCTools 用户指南：CT11 / CT13 / CT15 支持批量配置、日志终端、文件管理、参数管理、
配置备份和 OTA。CT16 暂不支持上述功能，原型明确列出限制，不因存在 UI 就假定设备已实现。

其他型号的能力需要逐项核对，未加入原型能力矩阵。固件升级后支持哪些能力应由真实协议和适配配置确认。
生产测试和设备激活另有各自协议与授权要求，不能从通用设备能力推断。

## 分阶段迁移

1. 固化经评审的导航、目标选择、输入预览和错误处理，保留原型作为验收参考。
2. 包装现有 DeviceManager，建立共享设备模型和能力服务；旧页面仍可继续使用现有服务。
3. 建立 TaskService、资源互斥和逐台结果，先迁移配置导入 / 导出，打通端到端流程。
4. 接入 OTA、批量参数、重启与激活，移除重复设备列表；逐项回归部分成功、失败、超时与重试。
5. 迁移详情、烧录和生产工作区；保持已有协议和硬件流程，逐个后端验收。
6. 验证三种版本、打包依赖和历史配置，再移除替代完成的旧界面。

每一阶段保留可运行版本，不一次性重写通信协议与全部界面。

## 评审重点

- 工位与研发场景是否都适合统一设备工作台？哪些入口应保留快捷路径？
- 配置导入是否采用“同页预览后执行”，单台编辑是否同样走确认预览？
- 首期是否同时开放逐台分配，还是先上线统一配置？
- 任务记录需要保留多久，日志导出与敏感字段怎样处理？
- 三种版本的功能边界与默认首页是否合理？
- 每台设备的固件适配结果怎样展示，以及设备忙时是排队还是拒绝？

上述内容用于团队决策，不表示这些正式功能已经实现。

## 原型工程结构

```text
index.html                   静态入口，可直接部署 GitHub Pages
src/app.js                   壳层、路由与交互事件绑定
src/core/store.js            设备注册表、能力与选择上下文
src/core/catalog.js          与现有源码对应的字段、烧录映射与搜索约束
src/core/workbook.js         Excel 评审读写
src/core/factory-profile.js  CTFP v1 评审编解码
src/core/tasks.js            模拟任务状态机、互斥、重试和人工确认
src/views/workspace.js       统一设备工作台
src/views/operations.js      页签内输入、文件校验、目标预览与执行
src/views/pages.js           任务、详情、烧录、生产与设置
src/ui.js / src/style.css    通用视觉组件与样式
server.mjs                   无外部依赖的本地静态预览服务
```

原型调度器与正式 Qt 任务服务采用相同职责划分，但不是可直接移植的实现。
后续用 Qt 复现经确认的交互；不将浏览器事件绑定代码迁入桌面程序。
